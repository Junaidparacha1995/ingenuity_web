# Ingenuity Systems — V6 Production Engineering Build

This version keeps the existing premium visual direction but fixes the production issues found in the V5 engineering audit.

## What changed in V6

- Cleaner navigation: **Home / Services / Industries / Work / Company**. **Work** is a direct top-level destination so it never expands the header or shifts the navigation. Selected work and engineering projects live together on that route.
- Every content page now has a semantic `<main>` landmark, a semantic primary `<nav>`, one H1, keyboard focus styling, and improved dropdown ARIA state.
- The accumulated stylesheet was split into five ordered layers:
  - `assets/css/core.css`
  - `assets/css/enhancements.css`
  - `assets/css/ui-system.css`
  - `assets/css/portfolio.css`
  - `assets/css/v6.css`
- Count-up metrics render their real value without JavaScript, then animate from 0 when visible.
- Unverified client-count metrics were replaced with inspectable website facts.
- `Case Studies` is positioned as **Selected Work** so public GitHub work is not presented as a client engagement.
- Contact form now posts to a real `/api/contact` endpoint with validation, honeypot protection, rate limiting, local persistence, and optional webhook/CRM delivery.
- Calendly opens in an embedded booking workspace instead of always throwing the visitor into a new tab.
- First-party interaction analytics are opt-in and post only approved event names to `/api/events`. No ad tracker is included.
- The RAG knowledge builder now materializes animated values correctly instead of indexing `0`.
- RAG sync reuses the existing vector store and uploads only changed knowledge documents.
- Stale/unverified chatbot fallback claims were removed.
- RAG responses return clickable website source references, use a hard output limit, and log request IDs server-side.
- The Node server no longer exposes the project root. Only approved assets/data/pages are public.
- Helmet CSP is enabled, compression is enabled, API limits are separated, and request timeouts are set.
- Dynamic canonical tags, Open Graph URLs/images, Organization/Breadcrumb JSON-LD, `robots.txt`, and `sitemap.xml` are generated by the production server.
- Proper 404 page and 404 HTTP status added.
- GitHub project metadata can be refreshed with `npm run sync:github` and remains cached if GitHub is unavailable.
- Responsive Unsplash images now include `srcset`, `sizes`, explicit dimensions, lazy loading, and high-priority loading only where useful.
- Long-running hero animation pauses when it leaves the viewport or the tab is hidden.

## Requirements

Use **Node.js 22 or newer** for the full production/RAG build.

## 1. Open in VS Code

Extract the ZIP and open the **entire project folder** in VS Code.

Do not open or copy only `index.html`; the site depends on the complete folder structure.

## 2. Install dependencies

From the VS Code terminal:

```bash
npm install
```

## 3. Create `.env`

Copy `.env.example` to `.env`.

Minimum local setup:

```env
PORT=3000
OPENAI_API_KEY=
OPENAI_MODEL=gpt-5.6-terra
```

For a production RAG chatbot, add your private server-side OpenAI key. Never put the key in HTML or browser JavaScript.

For production SEO, set your real live domain:

```env
SITE_URL=https://your-real-domain.com
```

## 4. Refresh public GitHub metadata (optional)

```bash
npm run sync:github
```

This updates `data/projects.json`. A `GITHUB_TOKEN` is optional but useful for higher API limits.

## 5. Build / sync the RAG knowledge base

```bash
npm run setup:rag
```

Unlike the earlier build, V6 reuses the existing vector store and only replaces changed knowledge files.

## 6. Start the production server

```bash
npm start
```

Open:

```text
http://localhost:3000
```

For development with automatic Node restarts:

```bash
npm run dev
```

### Clean URLs and VS Code

The site now uses production-style clean routes such as `/services/ai`, `/projects`, and `/pages/ai-maturity`. Old `.html` URLs redirect to the clean route when the Node server is running. Use `npm start` for normal development and testing; VS Code Live Server does not provide the route rewriting or backend APIs required by this build.


## Where website data goes

- **AI Maturity Assessment:** processed in the browser. The completed score/stage is stored in browser `localStorage` on that device. The assessment itself does not submit the answers to the server.
- **Solution Finder / interactive configurators:** processed in the browser unless a later CRM integration is explicitly added.
- **Contact form:** posts to `/api/contact`; accepted inquiries are written to private `.runtime/leads.ndjson`. If `CONTACT_WEBHOOK_URL` is configured, the lead is also forwarded to that CRM/automation endpoint.
- **AI Advisor:** the current question and recent in-page conversation history are sent to `/api/chat`, which sends the grounded request to the configured AI provider. The OpenAI request is made with `store:false`; the website does not write chat transcripts to the lead log.
- **Optional analytics:** only after consent, approved interaction events are written to private `.runtime/events.ndjson` and optionally forwarded to `ANALYTICS_WEBHOOK_URL`.
- **Scheduling:** strategy-call booking opens Calendly in an embedded frame; scheduling data is handled by Calendly under the configured Calendly account.

The `.runtime` folder and `.env` are private server files and are never served as public web assets.

## Contact form / CRM delivery

Accepted leads are validated and stored in `.runtime/leads.ndjson` for local development. The `.runtime` folder is never served publicly.

Before public launch, configure a secure CRM/email/automation webhook:

```env
CONTACT_WEBHOOK_URL=https://your-secure-lead-endpoint.example
REQUIRE_CONTACT_DELIVERY=true
```

With `REQUIRE_CONTACT_DELIVERY=true`, the form will not claim successful external delivery unless that integration is configured and responds successfully.

## Optional analytics webhook

The website contains an opt-in, first-party event layer. To forward approved events to your own analytics pipeline:

```env
ANALYTICS_WEBHOOK_URL=https://your-analytics-endpoint.example
```

Tracked event types include booking starts, contact submissions, project expansion, ROI interaction, maturity report download, system configuration, and chatbot engagement.

## Automated audit

Run:

```bash
npm run audit
```

It checks local references, duplicate IDs, one-H1 structure, landmarks, CSS migration, stale unsupported claims, and dependency policy.

## Important production inputs still required from you

The code is structured so these can be added without another redesign:

1. Your actual live domain for `SITE_URL`.
2. The real destination for leads: CRM, email automation webhook, or backend endpoint.
3. Approved client logos/testimonials/results if you want verified client case studies.
4. Real team/founder photography and bios if you want human-profile sections to move beyond placeholders/editorial imagery.
